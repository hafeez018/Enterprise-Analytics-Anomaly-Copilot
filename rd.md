You do not need an external database server (like PostgreSQL or MySQL) or existing company tables to run and showcase this project.

**SQLite is a serverless, file-based database.** It stores the entire relational database inside a single local file (`data/product_metrics.db`). The `data/setup_db.py` script automatically builds the tables (`users`, `events`, `orders`) and seeds them with 500 users, 60 days of activity, and an injected checkout bug on mobile devices. Running `python data/setup_db.py` creates this entire database locally in seconds.

## 🎯 The Business Problem

Product teams frequently require ad-hoc metric evaluations (e.g., *"Did mobile checkout conversion drop after the last release?"*). Traditional workflows require data teams to write repetitive SQL queries, export data into spreadsheets, run statistical checks manually, and draft summary emails.

This copilot eliminates this reporting friction while maintaining strict production safety:
1. **Zero Data Hallucination:** Computations are performed deterministically in SQL, NumPy, and Pandas—never estimated by the LLM.
2. **Self-Healing Execution:** Syntax errors are caught by interpreter feedback and automatically repaired without user intervention.
3. **Defense-in-Depth Security:** Multi-statement queries, DDL/DML mutations, and prompt injections are intercepted via Abstract Syntax Tree (AST) analysis and read-only engine locks.

## 🗄️ Relational Schema

The engine operates on a normalized event-driven product schema generated by `data/setup_db.py`:

```text
users
├── user_id (INTEGER, PRIMARY KEY)
├── signup_date (DATE)
├── device (TEXT: 'iOS', 'Android', 'Web')
└── plan (TEXT: 'Free', 'Pro', 'Enterprise')

events
├── event_id (INTEGER, PRIMARY KEY AUTOINCREMENT)
├── user_id (INTEGER, FOREIGN KEY -> users.user_id)
├── event_name (TEXT: 'page_view', 'add_to_cart', 'checkout')
└── event_date (DATE)

orders
├── order_id (INTEGER, PRIMARY KEY AUTOINCREMENT)
├── user_id (INTEGER, FOREIGN KEY -> users.user_id)
├── order_date (DATE)
└── amount (REAL)

```

> **Note:** The data generator injects a deliberate statistical conversion drop on mobile devices (`iOS`, `Android`) in the final 7 days of the generated data to evaluate the anomaly detector and insight engine.

## 🛡️ Security & Defense-in-Depth

The application implements a 3-layer security perimeter:

1. **AST Parsing (`sqlglot`):** Evaluates query syntax trees. Blocks destructive operations (`DROP`, `DELETE`, `UPDATE`, `INSERT`, `ALTER`), rejects stacked commands (semicolon injections), and enforces automated query `LIMIT` caps to eliminate memory exhaustion attacks.
2. **Engine-Level Isolation:** Database connections are established using the SQLite URI `file:data/product_metrics.db?mode=ro`. The operating system and SQLite engine reject any physical write operations even if AST validation is bypassed.
3. **Deterministic Temperature:** Query generation runs at `temperature=0.0` to eliminate non-deterministic hallucinations.
